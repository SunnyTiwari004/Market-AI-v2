# MARKET AI logical data model

System Design Gate 1, 2026-09-16. Design only: no schema code, migrations, records or fictional names are created. [PRD coverage](../product/PRD.md#prd-002-bounded-coverage) and the [synthetic data contract](SYNTHETIC_DATA_CONTRACT.md) govern this model. [Research methodology](../research/RESEARCH_METHODOLOGY.md) owns calculations; the model stores their inputs and reproducible outputs, not a second methodology.

## Identity, version and ownership conventions

Exactly 15 issuers, 12 listings, four sectors and four IPO offers exist in a complete Release-1 dataset. One Listed offer refers to an issuer already among the 12 listings; the other three issuers have no listing yet. A company is an Issuer with an eligible Listing, not a duplicated company record. Stock and historical IPO research can therefore resolve the same issuer without conflating the offer price and current stock price.

All dataset-owned records use a required dataset-version reference and deterministic opaque stable ID, generated from a namespace and an immutable seed identity key. Do not derive identity from a name, symbol, array position or wall clock. Logical keys survive regeneration; physical identity is the pair (dataset version, stable ID). Every relationship stays within that version, with referential integrity; the only cross-version link is optional dataset ancestry. Slugs/symbols are lookup attributes, not primary identities. No concrete ID values are assigned here.

The following entity catalog describes logical structures, not prescribed SQL table names. Unless marked optional, catalog fields are required. Financial fields may contain a value or an explicit unavailable reason: a required field slot does not require fabricating a value. Unique keys include dataset version. All content becomes immutable when its dataset is published; corrections create a new dataset version. Delete an unpublished draft only through developer tooling; never cascade-delete evidence out of a published dataset. No public write interface exists.

## Price history

PriceClose stores listing reference, TradingSession reference and strictly positive INR close, with optional unavailability reason instead of a close for an intentionally missing observation. Identity/uniqueness is listing/session; no duplicate session, price before listing or post-cutoff quote. The series uses a single declared unadjusted basis; v1 has no splits, dividends/total-return adjustment, OHLC or volume. These are not needed by the closing-chart contract. Financing/IPO share issuance is separately modeled and never silently treated as a split.

Eleven established listings cover two years of sessions. The IPO-linked listing covers sessions since listing, spanning at least 90 calendar days at the reference clock. No pre-listing padding. Each listing has many closes; each session has zero/one close per listing. The current quote is a selection of the last eligible close, not a separately editable price. A missing expected latest close is identified as stale/unavailable, not skipped without disclosure. Seed-owned prices are synthetic inputs, not calculated forecasts.

For a listing entering within the covered history, its supported listing date must be a declared TradingSession with a valid official synthetic first close; missing that initial close fails dataset validation. Established listings already active at the coverage start are base members; their earlier initial prices need not be stored. Index membership begins with the following common scheduled-session interval. After entry, an expected missing close cannot remove the constituent or reweight the aggregate: that interval is unavailable. All listings share the canonical market calendar; weekends/non-sessions are not gaps. Published Release-1 seeded broad/sector index history must be contiguous over supported scheduled intervals: unexpected missing eligible closes block dataset validation/publication. Runtime unavailable behavior and incomplete test fixtures do not waive this publication requirement.

## Financial statements

Choose a **typed period record with three typed statement groups**, not generic metric/EAV input rows. The bounded fields below give explicit units, sign and validation. EAV would require dynamic metric definitions, unit validation and joins for every financial rule; it offers no benefit for this known set. A small typed derived-output structure is allowed and is not an open-ended metric store.

Release-1 dataset design requires one common synthetic fiscal calendar for all issuers: identical full annual boundaries and quarter start/end dates, with no short/extended fiscal periods. Exact dates, accounting/reporting scope and currency establish peer-window compatibility; quarter labels alone do not. Supporting different fiscal calendars would require a separately specified alignment policy, not an implementation guess.

FinancialPeriod identifies issuer, annual/quarterly basis, period start/end, fiscal year/quarter, currency, reporting scope, publication timestamp, revision identity and its SourceDocument. Unique issuer/basis/start/end/revision; no overlapping quarters or duplicate revisions. One issuer has three annual and eight quarterly periods at the reference clock. Each period has exactly one IncomeStatement, BalanceSheet and CashFlowStatement group. Each source report supports one period; one source can contain all three groups. Prior snapshots select only reports published by their cutoff. No restatement rewriting within a published version; a corrected dataset must deliberately resolve revision selection.

| Statement group | Stored input fields | Constraints and purpose |
| --- | --- | --- |
| IncomeStatement | Revenue, operating profit (EBIT), finance interest expense, net income attributable to ordinary shareholders, weighted-average ordinary shares | Revenue and interest expense nonnegative; profits may be negative; weighted shares positive. One ordinary share class; no dilution/instrument complexity. EPS is calculated, never an independently supplied competing value. Supports growth, margins, coverage, P/E and peers. |
| BalanceSheet | Total assets, total liabilities, ordinary equity, gross interest-bearing debt, cash and cash equivalents, period-end ordinary shares | Assets/liabilities/debt/cash nonnegative; equity may be negative. Assets = liabilities + equity; debt <= liabilities; cash <= assets; shares positive. Supports leverage, net debt, ROE and IPO capital reconciliation. No current-ratio fields. |
| CashFlowStatement | Operating cash flow, investing cash flow, financing cash flow, capital expenditure outflow, opening cash, closing cash | OCF/ICF/FCF-financing are signed; capex is nonnegative and is a disclosed part of investing activity, not the whole investing flow. Opening cash + OCF + investing + financing = closing cash = balance-sheet cash. No FX effect in the single-currency v1 world. Free cash flow is OCF minus capex, not a second cash-flow statement total. |

Annual revenue/profit/interest and cash flows equal their four quarters where all four are within stored coverage. Annual balance-sheet and ending shares equal the last quarter, never the sum. Annual weighted shares equal the day-weighted quarterly averages under the fixed fiscal calendar. Consecutive quarter opening cash equals prior closing cash. Where a prior quarter lies outside the eight-quarter window, opening cash is a supplied report input with provenance, not fabricated from a missing row. Missing fields carry typed reasons; incomplete relationships cannot be asserted reconciled. Publication must follow period end. All periods use the same declared reporting basis; v1 seeds do not mix standalone and consolidated accounts or financial-sector accounting models.

For weighted-share reconciliation, compare the day-weighted annual average rounded to the declared six fractional digits using the common decimal rounding rule. This accounts for finite reporting precision; it does not permit arbitrary cash/statement reconciliation tolerances.

## Evidence, articles and concepts

EvidenceRecord is a narrow referential parent: ID, kind (article/document/concept), title, publishedAt, simulated provenance flag, content availability/reason and content digest. It owns common identity and reader metadata only. Exactly one matching typed child must exist; validate this invariant transactionally. It is not an unconstrained subjectType/subjectId relationship.

| Entity / purpose | Fields / required relationships | Constraints, lifecycle and ownership |
| --- | --- | --- |
| Publisher | ID, unique fictional name, simulated designation | One publisher to many Articles; seed input. No real publisher identity or external URL. |
| Article | EvidenceRecord ID as child key, publisher, body, category, relevance rationale | Separate from filings; 1:1 matching article parent. Publication is inherited from parent. Seed-owned copy, unchanged by level. Target coverage remains 32 articles per PRD. |
| SourceDocument | EvidenceRecord ID as child key, document type, body, optional issuer/offer and reporting-period metadata | Separate report/announcement/offer content. Issuer document requires issuer; offer document additionally requires that issuer's offer. Period report maps to FinancialPeriod; no fake downloadable URL. Readable body required for available status. PRD minimum remains 184 non-article documents. |
| Concept | EvidenceRecord ID as child key, unique concept key, definition, formula conditions, limitations, optional centrally owned illustrative example, level-specific explanatory text | Six reviewed concepts. These are teaching records, not issuer observations. Source counts distinguish concept content from financial reports. |
| EvidenceIssuer / EvidenceSector / EvidenceOffer / EvidenceMarket | Each is a separate join with evidence reference, typed target reference, rationale | Many-to-many with unique evidence/target pair; no dangling polymorphic targets. Articles may concern several issuers/sectors. At least one appropriate relevance link for financial articles/documents. |
| RecordedEvent | ID, occurredAt, publishedAt, event category, supported factual summary | Stored editorial event, not AI-generated cause. Typed EventIssuer/EventSector joins attach scope; EventEvidence joins attach actual supporting EvidenceRecords, all many-to-many unique pairs. Publication/cutoff gates visibility. |

EvidenceRecord is the stable citation namespace, so one report cited by multiple metrics counts once. Calculation provenance additionally points to typed financial periods and price observations through snapshot input relationships below. A synthetic price series is explicitly identified as a canonical dataset input, not a fictitious external document; no extra report is fabricated merely for a chart source chip. No article or document models an external publisher URL.

Scenario assumptions are canonical raw inputs, versioned with dataset and method; invalid ordering or future supporting evidence blocks publication. Financial/price input joins identify every quarter and peer observation used by TTM and scenarios. Raw statements remain canonical; persisted metrics and categories are immutable historical results of a specific methodology, not separately editable truths.

Result bundles are a fixed, versioned typed structure with named metric fields, decimal strings, availability and reason codes; not arbitrary JSON/EAV properties or presentation classes. Physical column/group mapping is decided during schema implementation. Foreign identities live in the typed relationships, with manifest checks ensuring the bundle refers only to those inputs. Dataset generation validates all field references and finding evidence before publication.

The three Stock cutoffs exist for each horizon even when a result is legitimately unavailable (for example long price history on the recent listing). They do not authorize extra companies or synthetic financial values. What Changed is a request-time comparison, not independently authored change rows. Decision answers/summary are views over the selected snapshot and finding catalog, not separate stored scores. No Ask conversation or generated answer persistence belongs in this model.

## Peers and discovery

Derive Stock peer candidates from the same sector, excluding self, requiring an eligible listing at the cutoff and the same reporting basis. With three current listings per sector this gives two candidates. Metric-specific comparability is checked by methodology; an ineligible peer is not replaced with another sector's company. No explicit peer graph is needed. IPO peers are eligible listed issuers in its sector, excluding itself when listed, at the IPO evaluation cutoff.

Theme and Collection are separate small entities: ID, unique slug, name and rationale. ThemeMembership and CollectionMembership each relate their parent to Listing with inclusion rationale and optional supporting EvidenceRecord; unique parent/listing, many-to-many. Exactly two themes and two collections remain the target. A collection is editorially selected but validated against any factual condition claimed by its title; it does not supply a research score. Sector scopes derive from Issuer. Methodology owns research categories and What Changed filters; membership never changes with explanation level.

## IPO offer and reconciliation

| Entity | Required fields and relationships | Constraints / time / ownership |
| --- | --- | --- |
| IpoOffer | ID, issuer, unique slug, open/close timestamps, expected listing date, optional actual listing timestamp and Listing link, low/high price band, optional final issue price and its publication time, lot size, pre-offer shares, fresh shares, OFS shares, issue-expense input, currency, terms-publication time and offer evidence | Four offers; one per issuer in v1. low > 0, high >= low; lot/share quantities are positive integers except fresh/OFS may be zero individually, not both. Final price, when published, lies within band. open <= close < actual listing. Link must match issuer; one Listed overlap. Inputs stored; status/amounts derived. |
| OfferProceedsUse | Offer, stable purpose key, fraction of net fresh proceeds and supporting evidence/publication time | One offer to many; unique purpose per offer. Fractions sum exactly to one for positive net fresh proceeds; amounts derive under the selected price basis. Zero net fresh proceeds has no positive allocation. These are explicitly modeled allocation proportions, not independently supplied contradictory amounts. |
| OfferHolder | Offer, stable holder key, fictional holder label, promoter/other flag, pre-shares, sold shares, fresh allocated shares, evidence | One-to-many; sum pre-shares = pre-offer shares; sum sold = OFS; sum fresh allocated = fresh issue shares. sold <= pre-shares. After shares = pre - sold + fresh allocated; no fractional holdings. No personal user data. |
| OfferReservation | Offer, investor category, shares reserved, evidence | Exactly the three supported categories; unique offer/category; sum reserved = fresh + OFS. All reserved quantities > 0 for the demonstration coverage. |
| OfferSubscriptionObservation | Offer/category, observedAt, subscribed shares, evidence | Unique offer/category/time; nonnegative subscribed shares; known no earlier than observed/publication time. Zero is a real observed zero, not missing. No observation before offer opens. No manufactured demand for Upcoming. |

Status at clock T: Listed if actual listing <= T and matching Listing exists; otherwise Upcoming if T < open; Open if open <= T <= close; otherwise Closed. Expected listing date never by itself makes an offer Listed. A supplied actual listing date in the future stays out of eligible current observations. Final price is used only after its publication cutoff; otherwise use the high band, labeled upper-band illustration. Terms requiring a price share that basis.

Total offer shares = fresh + OFS. Gross fresh proceeds = price basis × fresh shares; OFS proceeds = price basis × OFS shares; issue total = their sum. Net fresh proceeds = gross fresh minus issue expenses (nonnegative and <= gross fresh). Allocations use net fresh proceeds and explicitly show expenses. Post-offer shares = pre-offer + fresh; OFS does not create shares. Holder after-shares sum to this total; pre/post percentages use their respective denominators and are derived, not supplied duplicates. Minimum application = lot size × selected price basis, with its basis shown. Subscription = subscribed/reserved at the latest compatible observation; categories absent at that instant stay unavailable, not mixed with future observations. Historical offer updates remain source records. Finalized Listed terms reconcile with listing share history and financial publication timing without overwriting earlier statements.

Every holder/reservation/proceeds input inherits its supporting evidence publication cutoff. Select only eligible inputs; a later final allocation is not evidence of earlier knowledge. v1 terms, quantities and allocation proportions are fixed within each offer; only disclosed final price and subscription observations advance through the lifecycle. A terms amendment would need explicit versioned term records in a later model change, not overwriting this dataset. For a Listed offer, its final price and all required offer evidence must be published before its research evaluation cutoff. Unsupported earlier fields remain unavailable. Rounding allocation amounts for display may create a display remainder; show the exact reconciled total and explain rounding, never modify canonical amounts to hide it.

## Market context

Numeric Home/Explore context is deterministically derived from eligible closes and research snapshots; no parallel editable MarketSnapshot numbers. A MarketBriefing stores ID, cutoff, method reference, editorial meaning/watchpoint keys and links to RecordedEvents/EvidenceRecords, unique cutoff within the version. Three cutoffs support the PRD market snapshots: service output combines this stored narrative context with computed numbers. Sector context is keyed by sector at the same cutoff. Labels cannot assert causal return contributions. Market identity remains one broad index, not a second input price universe.

## Money, units and time

| Type | Logical precision and transport |
| --- | --- |
| INR amounts and observed share prices | Exact decimal, up to 20 integer digits and two fractional digits. Reject excess precision at input rather than silently round. No binary floating point authority. INR throughout v1; no conversion subsystem. |
| Computed EPS, per-share scenario values | Decimal calculation at at least 34 significant digits; preserve up to 12 fractional digits in reproducible output, round only for display to two decimals. |
| Ratios, fractional returns, percent values | Decimal calculation at at least 34 significant digits; output canonical precision 12 fractional digits. Ratio and percentage-point units are distinct. Formula comparisons use unrounded calculated results. |
| Share counts | Exact nonnegative integers with up to 20 digits; weighted-average shares permit six fractional digits. JS transport uses decimal strings, never lossy numeric coercion. |
| Scores/categories | Categorical enums only for pillars/Picture/Risk/confidence; no 0–100 score field or confidence percentage. |
| Dates and periods | ISO date-only trading/reporting dates; start/end inclusive under explicit fiscal year/quarter metadata. No machine timezone conversion of dates. |
| Timestamps | UTC instants with explicit offset on ingestion; calendar interpretation Asia/Kolkata. Publication, event occurrence, cutoff, session close and real generatedAt are different fields. |

Display rounding is decimal half-away-from-zero; output serialization also uses that rule. Formula/rule comparisons precede serialization. Decimal division and square root in the methodology use the same precision context; expected-value tests freeze these rules. Reject NaN/infinity/overflow, propagate invalid results explicitly. Units shown in lakhs/crores are presentation conversions from the canonical INR quantity, never differently scaled stored truth.

## Access patterns and integrity handoff

Likely indexes: version + URL symbol/issuer slug/offer slug; issuer sector; listing/session date; issuer/period basis/end/publication; listing/cutoff/horizon/method; evidence ID; article publication plus typed issuer relevance; offer dates/listing date and category/observation time. Join pairs are unique. Do not index every assessment field; 12 research rows per current horizon fit ordinary filtering. Derived IPO status can be evaluated from four offers, not separately maintained status indexes.

Dataset import, evidence subtype/link creation, report groups, offer reconciliation and complete snapshot generation are transaction boundaries. Build an inactive dataset, validate the whole version, then atomically publish its manifest; request operations pin one version. A failed generation cannot expose half a snapshot or half the IPO ownership ledger. Details belong to [backend integrity](../architecture/BACKEND_ARCHITECTURE.md#transactions-and-publication). This model creates no migration or data record. The [first vertical slice](../architecture/BACKEND_ARCHITECTURE.md#first-vertical-slice) must prove these boundaries at small scale before the full dataset is populated.
